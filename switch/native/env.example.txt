# Run options of the native port on the Switch. Copy to the SD card as
#   switch/centollos/native/env.txt
# (scripts/switch/push.sh --native-env switch/native/env.example.txt). One NAME=value per line,
# nothing else on it; a line starting with # is ignored. Without the file the Switch defaults
# apply:
#   COS_DISC=/switch/centollos/GZLE01.iso   (the disc image: push.sh --disc or --game)
#   COS_RUN_DIR=/switch/centollos/native    (where the harness writes backtrace.txt)
#   COS_PERF_EVERY=60                               (a "[cos] perf" line every 60 game frames)
#   COS_HITCH_MS=50                                 (a "[cos] hitch" line for a frame over 50 ms)
#   COS_FPS_OVERLAY=1                               (fps / game ms / render ms / draws panel, top left;
#                                                    COS_FPS_OVERLAY=0 hides it)
#   COS_STALL_S=90                                  (exit 11 after 90 s without a game frame)
#   COS_ASPECT=16:9                                 (widescreen; 4:3 is the GameCube picture)
#   COS_FB_SCALE=1.5                                (internal resolution 1280x720, see below)
# Any COS_* variable of native/README.md ("Running centollos (phase 6)") works here. Remove the # in
# front of one of these to use it:
#
# Exit 0 when the title's sea is reached (milestone M7, "opening"):
#COS_MILESTONE=opening
#
# Exit 0 after this many game frames:
#COS_FRAMES=1800
#
# Log every scene the game creates:
#COS_TRACE=scene
#
# Start-up check only: every static constructor ran and the 502 actor profiles are in place:
#COS_SMOKE=static-init
#
# Write through a null pointer, to check the crash report ("[cos] CRASH" in the log, then
# Atmosphère ends the app with its own report):
#COS_SMOKE=crash-test
#
# Do not start JAudio and the DSP (the game is silent either way for now):
#COS_AUDIO=off
#
# Dawn's GL queue: drain the GPU with glFinish after every submission, as builds before the GL fence
# queue did (to compare frame times; "glFinish" in the perf-switch line):
#COS_SWITCH_GL_FINISH=1
#
# Internal resolution (Aurora's frame-buffer scale of the 640x480 EFB, at 16:9): 1.5 = 1280x720
# (default), 1.125 = 960x540, 1.0 = 854x480. Fewer pixels for the GPU; the picture is resampled to
# the screen:
#COS_FB_SCALE=1.125
#
# Pin the render worker to core 2 and JAudio's and the DVD thread to core 1 (default: every helper
# thread prefers core 1 or 2 in turn):
#COS_SWITCH_CORES=pinned
# Or the render worker alone on core 2 and every other thread (the game's too) on cores 0-1, so that
# nothing queues on the worker's core (compare the "[cos] perf-switch threads" lines):
#COS_SWITCH_CORES=isolate
#
# Leave Aurora's pipeline compile thread wherever the default puts it (default: never on the render
# worker's core):
#COS_SWITCH_COMPILE_CORE=off
#
# No GPU timer queries (GL_TIME_ELAPSED_EXT around every render pass, the "perf-switch gpu" line and
# "gpu" on the overlay); for an A/B run against their small cost:
#COS_SWITCH_GPU_TIMER=0
#
# Dawn's GL context without error checking (KHR_no_error: Mesa skips the checks of every GL call;
# "[dawn] COS_SWITCH_GL_NO_ERROR" in the log says whether Mesa accepted it). To compare the
# "dawn gl replay" times; a GL error then has undefined results:
#COS_SWITCH_GL_NO_ERROR=1
#
# Bind Aurora's uniform buffer per draw again instead of once per 64 KiB window (A/B only; see
# "UBO binds" in the perf-switch replay line and docs/SWITCH_PERF_STUDY.md, section 7):
#COS_SWITCH_GL_UBO_WINDOW=0
#
# Issue every render pipeline's whole GL state on each pipeline change again (A/B only):
#COS_SWITCH_GL_STATE_CACHE=0
#
# Delete GL textures and buffers at once instead of after the GPU is done with them (A/B only: the
# render worker then waits for the previous frame's GPU work at the first clear of every frame; see
# the "[cos] perf-switch gl stall" line):
#COS_SWITCH_GL_DEFER_DELETE=0
#
# Boot pipeline warm-up (docs/SWITCH_BUILD.md, "Pipeline precompile"): boot (default) shows a
# "Preparing shaders" loading screen before the boot logo until the boot path's pipelines are
# built (about 20 s; needs the bundled initial_pipeline_cache.db), then builds the rest behind the
# logos and menus ("Shaders N/M" in a corner) until the game first enters its PLAY scene; full keeps
# the loading screen until every known pipeline is built (2-3 minutes, then no stutter from a known
# pipeline); all has no loading screen and builds every one (into gameplay: a stutter per pipeline);
# off builds each when first drawn:
#COS_PRECOMPILE=full
#
# Share of the time the boot warm-up may build pipelines behind the logos and menus (boot, after the
# loading screen; default 0.5). 1 or 0: back to back (faster warm-up, 4-7 frames/s meanwhile):
#COS_PRECOMPILE_DUTY=0.3
#
# Only a warm-up build slower than this many ms (a shader cache miss) makes the next one wait for
# the duty above; faster builds (cache hits, ~12 ms) follow at once (default 25; 0: every build waits).
# It also decides the loading screen below:
#COS_PRECOMPILE_SLOW_MS=25
#
# When boot and full show the "Preparing shaders" loading screen: auto (default) only when the first
# builds are slower than COS_PRECOMPILE_SLOW_MS (a cold shader cache: the first start, new shaders);
# with the cache warm the logos come up at once and the priority pipelines build behind them.
# always: the loading screen as before; never: no loading screen:
#COS_PRECOMPILE_SCREEN=always
#
# Mesa's shader cache drops entries unused for this many runs (default 5; 0: never), in a background
# compaction this many seconds into a run (default 60):
#MESA_SHADER_CACHE_PRUNE_BOOTS=5
#MESA_SHADER_CACHE_PRUNE_DELAY=60
#
# Frame rate cap of the "Preparing shaders" loading screen (default 10; each present needs the render
# worker and the GL context the compile thread builds with):
#COS_PRECOMPILE_SCREEN_FPS=10
#
# No "[cos] precompile" progress lines:
#COS_PRECOMPILE_LOG=0
