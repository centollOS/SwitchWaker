# Run options of the native port on the Switch. Copy to the SD card as
#   switch/switchwaker/native/env.txt
# (scripts/switch/push.sh --native-env switch/native/env.example.txt). One NAME=value per line,
# nothing else on it; a line starting with # is ignored. Without the file the Switch defaults
# apply:
#   COS_DISC=/switch/switchwaker/GZLE01.iso   (the disc image: push.sh --disc or --game)
#   COS_RUN_DIR=/switch/switchwaker/native    (where the harness writes backtrace.txt)
#   COS_STALL_S=90                                  (exit 11 after 90 s without a game frame)
#   COS_ASPECT=16:9                                 (widescreen; 4:3 is the GameCube picture)
#   COS_FB_SCALE=1.5                                (internal resolution 1280x720, see below)
# The in-game options menu (Minus) saves its values to native/user/settings.ini; a line here
# wins over that file (the menu then shows the row as fixed).
# Any COS_* variable of native/README.md ("Running switchwaker (phase 6)") works here. Remove the # in
# front of one of these to use it:
#
# A measuring run (the defaults are for players: no perf or hitch lines, no frame-rate panel): a
# "[cos] perf" line every 60 game frames, a "[cos] hitch" line for a frame over 50 ms, the panel:
#COS_PERF_EVERY=60
#COS_HITCH_MS=50
#COS_FPS_OVERLAY=1
#
# The debug server for development (docs/DEBUG_SERVER.md; off by default, local network only, no
# password): deploy and restart over the network, the live log, screenshots, button presses, warps
# (scripts/switch/switchwaker_debug.py):
#COS_DEBUG_SERVER=1
#
# The live log over USB to scripts/switch/usb_log.py (off by default: it holds the console's USB
# port for the whole run; the log file on the SD card is written either way):
#COS_USB_LOG=1
#
# Exit 0 when the title's sea is reached (milestone M7, "opening"):
#COS_MILESTONE=opening
#
# Exit 0 after this many game frames:
#COS_FRAMES=1800
#
# Log every scene the game creates:
#COS_TRACE=scene
#
# Start-up check only: every static constructor ran and the 502 actor profiles are in place:
#COS_SMOKE=static-init
#
# Write through a null pointer, to check the crash report ("[cos] CRASH" in the log, then
# Atmosphère ends the app with its own report):
#COS_SMOKE=crash-test
#
# Do not start JAudio and the DSP (the game is silent either way for now):
#COS_AUDIO=off
#
# Internal resolution (Aurora's frame-buffer scale of the 640x480 EFB, at 16:9): 1.5 = 1280x720
# (default), 1.125 = 960x540, 1.0 = 854x480. Fewer pixels for the GPU; the picture is resampled to
# the screen:
#COS_FB_SCALE=1.125
#
# Journal of Aurora's sqlite caches (user/cache/dawn_cache.db, pipeline_cache.db; docs/SWITCH_BUILD.md,
# the paragraph on Aurora's caches before "Pipeline precompile"): persist (default; a game closed with HOME mid-write is rolled back at the next
# start), truncate, delete, or memory (no journal file; a kill mid-write can damage the cache, which
# is then deleted and rebuilt):
#COS_SWITCH_SQLITE_JOURNAL=memory
#
# Boot pipeline warm-up (docs/SWITCH_BUILD.md, "Pipeline precompile"): boot (default) shows a
# "Preparing shaders" loading screen before the boot logo until the boot path's pipelines are
# built (about 20 s; needs the bundled initial_pipeline_cache.db), then builds the rest behind the
# logos and menus ("Shaders N/M" in a corner) until the game first enters its PLAY scene; full keeps
# the loading screen until every known pipeline is built (2-3 minutes, then no stutter from a known
# pipeline); all has no loading screen and builds every one (into gameplay: a stutter per pipeline);
# off builds each when first drawn:
#COS_PRECOMPILE=full
#
# Share of the time the boot warm-up may build pipelines behind the logos and menus (boot, after the
# loading screen; default 0.5). 1 or 0: back to back (faster warm-up, 4-7 frames/s meanwhile):
#COS_PRECOMPILE_DUTY=0.3
#
# Only a warm-up build slower than this many ms (a shader cache miss) makes the next one wait for
# the duty above; faster builds (cache hits, ~12 ms) follow at once (default 25; 0: every build waits).
# It also decides the loading screen below:
#COS_PRECOMPILE_SLOW_MS=25
#
# When boot and full show the "Preparing shaders" loading screen: auto (default) for the whole
# warm-up (about 2 minutes, once) when the shader cache is cold (the first start, new shaders, a new
# Mesa: the first builds slower than COS_PRECOMPILE_SLOW_MS) or the last warm-up did not finish, so
# the title and menus never stutter on a compile afterwards; with the cache warm the logos come up at
# once and the warm-up builds behind them. priority: the earlier auto (the screen for the boot path's
# pipelines only, the rest behind the logos and menus with a hitch per cold build); always: the
# priority screen whenever they are not built; never: no loading screen:
#COS_PRECOMPILE_SCREEN=priority
#
# auto shows its loading screen only when the slow work left would take more than this many seconds
# (default 3); less is built behind the logos:
#COS_PRECOMPILE_SCREEN_MIN_S=3
#
# Language of the loading screen and the options menu (default: the console's; es = Spanish,
# anything else English):
#COS_LANG=es
#
# Mesa's shader cache drops entries unused for this many runs (default 5; 0: never), in a background
# compaction this many seconds into a run (default 60):
#MESA_SHADER_CACHE_PRUNE_BOOTS=5
#MESA_SHADER_CACHE_PRUNE_DELAY=60
#
# Frame rate cap of the "Preparing shaders" loading screen (default 10; each present needs the render
# worker and the GL context the compile thread builds with):
#COS_PRECOMPILE_SCREEN_FPS=10
#
# No "[cos] precompile" progress lines:
#COS_PRECOMPILE_LOG=0
#
# GPU cost per pixel (docs/SWITCH_PERF_STUDY.md, section 8). The forest mist is drawn at 1/4 of the
# resolution by default (same blend; 0 draws it as before, 2 or 3 other sizes):
#COS_MIST_LOWRES=0
#
# The sky at 1/2 of the resolution (off by default; softer horizon clouds):
#COS_SKY_LOWRES=2
#
# Dynamic resolution of the 3D (off by default): 1.5 -> 1.25 -> 1.125 when the GPU p95 stays above
# 30 ms, back up with headroom; the 2D keeps 1280x720. fixed:<scale> pins one level:
#COS_DYNRES=1
#COS_DYNRES=fixed:1.125
#
# GPU time per draw-list bucket in the perf-switch "gpu groups" line (2: per J3D material too):
#COS_GPU_GROUPS=1
#
# FPS overlay (off by default; fps / game ms / render ms / draws panel, top left), its detail: full
# (default) or compact (frame rate and game time on one line); and the "[cos] perf" / "perf-switch"
# lines in the log (0 hides them; the options menu sets all three):
#COS_FPS_OVERLAY=1
#COS_FPS_OVERLAY_DETAIL=compact
#COS_PERF_LOG=0
#
# HD textures (docs/HD_TEXTURES.md): replace the game's textures from the pack copied with
# scripts/switch/push_hd_pack.sh into native/user/hd_textures (convert it with
# scripts/hd/build_hd_pack.sh PACK.7z --max-size 512). Off by default. GPU memory the pack may use
# (default 512 MiB) and an "[cos] hd-textures" line every 300 frames (hits, loads, MiB, ms).
# The options menu's "Texturas HD" switches it at run time (a value here locks it):
#COS_HD_TEXTURES=1
#COS_HD_BUDGET_MB=512
#COS_HD_STATS_EVERY=300
