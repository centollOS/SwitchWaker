# Disc-mapped structs checked by cos_layout_check (docs/NATIVE_PORT_PHASE4_6.md, step 4.0c).
#
# A struct belongs here when the game reads it straight out of a file loaded from the disc (or a
# file it writes, like the save): its host layout must equal the GameCube layout, which the
# decomp records as /* 0xNN */ comments before each field and `// Size: 0xNN` after the brace.
# native/tools/layout_check.py turns those into static_asserts; the checks that fail until their
# format step lands are listed in layout_xfail.txt. A struct changed to BE(T)/OFFSET_PTR by a
# phase 4 step goes (or stays) here.
#
# Format: a header path relative to game/include at the start of a line, then its structs
# indented, one per line, by qualified name. A struct line may add `size=0xNN` and
# `<field>=0xNN` for what the decomp does not comment (they must agree with any comment there).
# Each group names the step that owns it.
